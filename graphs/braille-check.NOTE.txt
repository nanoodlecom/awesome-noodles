# recipe-note
A word you cannot see, only feel. Braille is a positional code: a letter is nothing but a set of raised dots inside a fixed 2-by-3 cell, and a single dot is the difference between one letter and another - D (dots 1,4,5) and F (dots 1,2,4) share two of three dots. This flow makes that code a planned, measurable quantity - and then it does something about a miss. Give it a plaque setting and a GLM director picks one word from a menu built for distinct dot patterns (BRAVE, LIGHT, PLANT, MUSIC, QUILT) and writes a BRAILLE CARD: the word, and for each letter its exact raised-dot set, looked up in the Grade-1 dot table printed in the director's own prompt, plus the plaque's FRAME - one material, one dot colour. A second GLM turns the card into one painter prompt that demands a single row of exactly five large cells, every cell showing all six dot positions as faint shallow dimples with only the carded dots raised as large dark domes - and no printed letters, words or numbers anywhere, because print would cheat the code: the word must exist only as dots. Muse paints it. A blind Gemini reader, who never saw the word or the card, reports how many cells it sees and, cell by cell, exactly which dot positions stand raised, plus any printed text in the picture. A GLM auditor decodes the reader's dot sets with the same table and scores CELLS (X of 5 letters whose dot set is exactly right), MISSING DOTS and EXTRA DOTS (each named by cell and dot number), the DECODED word the dots actually spell, and TEXT LEAK. A Decide judge headlines round 1: reads exactly, letters drifted, unreadable, or print cheat.

That verdict is not where this flow stops - the loop closes, per the standing rule that a created asset ends in the corrected asset, not in text. A GLM editor reads the card, the read and the audit and writes ONE concrete edit instruction: the full target end state (all five cells carrying exactly their carded dot sets, the plaque, background and framing unchanged, no print anywhere) plus the audit's specific failures as extra demands - raise a dome at cell 3 dot 6, flatten the extra dome at cell 1 dot 2, strip the printed caption - naming the cells already exact as keepers that must be left alone. Muse Edit applies those notes to the round-1 picture. The corrected plaque is the flow's deliverable. A second blind reader re-reports it, and the same auditor scores round 2 against the same card, so the fix is itself audited and the reader can see exactly what the edit bought - or cost. The Decide verdict stays, demoted to a side output on round 1.

Why this axis is new: the catalog's nearest neighbours encode with meaning, not position. Hidden word spells DREAM from the initials of five shelf objects - the letters live in the objects' names, so the audit is object identity and order. Pictogram check decodes conventional glyphs for the message a stranger receives - the audit is gist. Braille has no semantics to fall back on: the same dome, moved one position down, is a different letter, and the audit is dot-set fidelity per cell, the finest-grained positional score in the catalog. It also names a failure no other flow can state - TEXT LEAK as a cheat: a painter that quietly prints the word under the dots has produced a perfect-looking plaque that says nothing to a fingertip, and every beauty or presence judge would pass it. And the modality is tactile: this is the one catalog picture whose content is addressed to touch, with vision acting only as the measuring instrument.

Honest limits, in the open: this is Grade-1 (uncontracted) braille with textbook dot numbering - real-world signage adds contractions, capital signs and formatting this flow deliberately does not attempt, and the NOTE of a run should say so rather than upgrading the claim. The raised-versus-dimple distinction is the reader's visual judgement from shading and gloss; a dome painted ambiguous sits on that border, and the read records it as the reader called it. The director encodes from a table printed in its own prompt, so a card error is possible in principle - that is why the auditor decodes from the same printed table and the card is published with the graph's run: a wrong card would be visible as a card-versus-table mismatch, not hidden inside a score. The fix round has its own limit: an edit model asked to raise or flatten one dome in a grid can shift a neighbour - that is exactly what round 2's MISSING and EXTRA lines are for, and both audits are printed so the reader can see the trade. One repair round is unrolled, not a loop - if round 2 still drifts, the flow shows the drift rather than spending again.

The painter's own drift is geometric: the dimple fields run three columns wide in places and a partial fourth dimple row sits under cells 3-5, so cell boundaries exist only as spacing. The editor's notes named the missing and extra domes by cell and position, and the corrected plaque is visually verified - same stone, same framing, dome groups that under the original five-grouping sit at or near the carded sets. But the blind re-reader segmented the corrected plaque into EIGHT cells, splitting the wider groups at their internal gaps, and the re-audit therefore scored CELLS 1 of 5, DECODED L?I?? - worse on paper than round 1 while the domes themselves moved toward the card. That is this flow's honest headline limit, and it is a finding, not a rounding error: with no visible cell frame, a blind reader's grouping is itself a variable, and the repair round can fix dots but not segmentation.
