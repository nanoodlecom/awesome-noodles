# recipe-note
Rewrites a short draft comment so it reads like a person typed it, without changing what it says. This is Nano Maxi's humanize-comment flow v2.5. Four writers rewrite the same draft in parallel, each with its own voice line on a shared base prompt: Qwen3.8-27B Novelist (friend), DeepSeek V4.1 Flash 1017 (forum), Gemma-4-12B Starry Ocean (peer) and Qwen3.8-27B antislop (plain), all reasoningEffort none and maxTokens 600. Each rewrite is joined under a fixed label ([A]..[D]) next to the [ORIGINAL] draft and the post context; the labels are part of the judge joins' separators, so they always stay with their text. A GLM-5.3 decider first checks each rewrite for faithfulness (who said or did what, no new facts, numbers, qualifiers or names, no garbled names, main question and disclosure kept), disqualifies unfaithful or sloppy ones, ranks the rest and picks the most human faithful one, or ORIGINAL if every rewrite is disqualified. It never picks a near-verbatim copy of ORIGINAL.

Inputs: **Draft** (required; the comment to rewrite, up to about 1500 characters, any language), **Context** (required; the post or thread, plain text, up to about 3500 characters) and optional **Guidance** (what the comment should do; default "a friendly, specific reply"). The graph exports the decider's text: one JSON object {"winner": "ORIGINAL|A|B|C|D", "ranked": [{"label", "faithful", "note"}, ...], "disqualified": {...}, "why": "...", "text": "..."}, where text is the winning rewrite and ranked lists the rewrites best first with a per-rewrite faithful flag. When a writer was skipped, ranked may list only the rewrites the decider actually saw (seen in testing: 3 entries, with the missing writer under disqualified).

The prompts and labels are locked: the four writer nodes and the decider carry fields.locked, so their system prompts (the spec's v2.5 writer prompts and decider rubric) are not tool inputs and every run uses the stored values. The tool schema is just Draft, Context and Guidance. The block labels "[ORIGINAL]", "[A]" to "[D]" are fixed in the judge joins' separators rather than separate inputs. The only prompt change from the spec's v2.5 is the decider line Nano Maxi approved for v2.3: "A missing [X] block means that writer failed."

On 20 October 2026 three v2.5 runs through nanoodle-js main (9b78fea, the engine with per-node timeout, skip and lock) reported $0.00099 (CI post, 14 to 6 minutes; winner B, 18 s), $0.00116 (prompt-injection reply to an agent; winner C, 15 s) and $0.00081 with Writer B forced to time out (cost marked inexact; winner A, B listed as disqualified, 15 s). These are model costs before the 20% markup (about $0.0012 to $0.0014 after). The catalog forecast is $0.005369 before markup ($0.006443 after). A full-maxTokens worst case with maximum-length Draft and Context is about $0.0078 to $0.0085 before markup ($0.0094 to $0.0101 after). Prices are observations, not caps.

Hosted on mcp.nanoodle.com the graph pins an x402 deposit in USD: $0.0133, used as is with no multiplier (unchanged from v2.3). The XNO amount is that pin divided by the NanoGPT x402 rate, rounded up to 0.00000001 XNO, plus a random matching tag of 0 to 0.00009999 XNO (widened to 0 to 0.00999999 XNO only if 50 tagged amounts in a row collide with open quotes). There is no fixed XNO ceiling (it rises as XNO falls); the USD ceiling is the pin plus the tag's value. A successful run settles at real cost plus 20% and the rest comes back as change. Cost is capped at the deposit. The pin covers the full-maxTokens worst case about 1.3x to 1.4x and a typical run about 10x. If a run fails, a known payer is refunded the full paid amount. If the payer account is unknown, the money stays in the wallet until the operator resolves it. A refund send that fails is retried for about 16 hours and may then need manual repair.

Timeouts and failed writers: each writer has timeoutMs 60000 (the spec's 60 s writer timeout) and onError "skip". A writer that errors (for example an HTTP 400 or 503 from its host) or runs past 60 s is skipped and recorded in the run's errors. Its labelled block is simply left out of what the decider reads, and the decider treats a missing block as a failed writer. If all four writers fail, the decider sees only the context and [ORIGINAL] and returns ORIGINAL. A skipped writer that never reported a price makes the run's cost inexact. These keys need a nanoodle engine with per-node timeout, skip and lock support (nanoodle-js PR #46, merged on main as 9b78fea but not yet released on npm); older engines ignore them, so they show the prompts as inputs again and fail the whole run on one writer error.
