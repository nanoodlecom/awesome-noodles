# recipe-note
Rewrites a short draft comment so it reads like a person typed it, without changing what it says. This is Nano Maxi's humanize-comment flow v2.5. Five writers rewrite the same draft in parallel, each with its own voice line on a shared base prompt: Qwen3.8-27B Novelist (friend), DeepSeek V4.1 Flash 1017 (forum), Gemma-4-12B Starry Ocean (peer), Qwen3.8-27B antislop (plain) and Inception Mercury 3 (quick; added 20 October 2026 at Mikkel's request), all reasoningEffort none and maxTokens 600. Each rewrite is joined under a fixed label ([A]..[E]) next to the [ORIGINAL] draft and the post context; the labels are part of the judge joins' separators, so they always stay with their text. A GLM-5.3 decider first checks each rewrite for faithfulness (who said or did what, no new facts, numbers, qualifiers or names, no garbled names, main question and disclosure kept), treats any added explanation, generalization or new claim as unfaithful (when unsure, unfaithful), disqualifies unfaithful or sloppy ones, ranks the rest and picks the most human one that is not disqualified, or ORIGINAL if every rewrite is disqualified. It never picks a near-verbatim copy of ORIGINAL.

Inputs: **Draft** (required; the comment to rewrite, up to about 1500 characters, any language), **Context** (required; the post or thread, plain text, up to about 3500 characters) and optional **Guidance** (what the comment should do; default "a friendly, specific reply"). The graph exports the decider's text: a single JSON object and nothing else: {"winner": "ORIGINAL|A|B|C|D|E", "text": "...", "why": "...", "ranked": [{"writer", "model", "text", "faithful", "disqualified", "reason"}, ...]}, where text is the winning rewrite. ranked always has 5 entries, not-disqualified first and best first; each entry carries that candidate's model name (copied from its label line) and its full rewrite. faithful is about facts only, disqualified is true for any reason (unfaithful, style, banned phrase, near-copy, dropped direct address, missing), and only an entry with disqualified:false can win. A skipped writer is still listed, as {writer, faithful:false, disqualified:true, reason:"missing"} with an empty text. The texts are copied by the decider model, not by the engine, so a rare small wording change is possible (seen once in testing: "gets lost" became "is lost"); compare them with the writers' outputs when exact text matters.

The prompts and labels are locked: the five writer nodes and the decider carry fields.locked, so their system prompts (the spec's v2.5 writer prompts and decider rubric) are not tool inputs and every run uses the stored values. The tool schema is just Draft, Context and Guidance. The block labels "[ORIGINAL]" and "[A] <model>" to "[E] <model>" (each writer's letter and model name, for example "[E] inception/mercury-3") are fixed in the judge joins' separators rather than separate inputs. Changes from the spec's v2.5 decider prompt, all approved by Nano Maxi: the v2.3 line "A missing [X] block means that writer failed.", a missing or empty writer always listed in ranked, a stricter faithfulness rule (no added explanation, generalization or new claim), a role rule (changing what someone is or did, such as roles or who funded, bought or said something, is unfaithful even by paraphrase), per-entry faithful/disqualified/reason, a single-JSON-object output with text inside it, a near-copy rule (a rewrite that keeps most of the draft's sentences or word order is disqualified; prefer the most freshly-phrased faithful rewrite), a direct-address rule (don't pick a rewrite that drops the draft's direct address to the person), and model and text in every ranked entry. Every writer prompt also asks to skip canned praise but keep real warmth toward the person (talk to them, react to their point, keep a greeting or thanks if the draft has one). The decider's maxTokens is 6000 so it can copy five full rewrites.

On 20 October 2026 three runs of this graph through nanoodle-js main (9b78fea) on two of Nano Maxi's live cases reported $0.00364 (a reply to @pursekeeper's week-7 post; winner E, Mercury 3, 45 s), $0.00287 (an answer to APIS's "what is your rule?"; winner C, which opens "Hi APIS.", 16 s; writer D failed transiently and was skipped, so the cost is marked inexact) and $0.00229 with Writer C forced to time out (week-7 post; winner B, 18 s; D also failed transiently). The decider alone was $0.0019 to $0.0025 of each run. Each returned valid JSON only with 5 ranked entries carrying model names. These are model costs before the 20% markup (about $0.0027 to $0.0044 after). The catalog forecast is $0.009173 before markup ($0.011008 after). A full-maxTokens worst case with maximum-length Draft and Context and a full 6000-token decider reply is about $0.0121 to $0.0129 before markup ($0.0146 to $0.0155 after). Prices are observations, not caps.

Hosted on mcp.nanoodle.com the graph pins an x402 deposit in USD: $0.0133, used as is with no multiplier (unchanged from v2.3). The XNO amount is that pin divided by the NanoGPT x402 rate, rounded up to 0.00000001 XNO, plus a random matching tag of 0 to 0.00009999 XNO (widened to 0 to 0.00999999 XNO only if 50 tagged amounts in a row collide with open quotes). There is no fixed XNO ceiling (it rises as XNO falls); the USD ceiling is the pin plus the tag's value. A successful run settles at real cost plus 20% and the rest comes back as change. Cost is capped at the deposit. The pin no longer covers the full-maxTokens worst case (about 0.86x to 0.91x, so the deposit caps the cost in that case); it covers the catalog forecast about 1.2x and a typical run about 3x to 6x. If a run fails, a known payer is refunded the full paid amount. If the payer account is unknown, the money stays in the wallet until the operator resolves it. A refund send that fails is retried for about 16 hours and may then need manual repair.

Timeouts and failed writers: each writer has timeoutMs 60000 (the spec's 60 s writer timeout) and onError "skip". A writer that errors (for example an HTTP 400 or 503 from its host) or runs past 60 s is skipped and recorded in the run's errors. Its labelled block is simply left out of what the decider reads, and the decider treats a missing block as a failed writer. If all five writers fail, the decider sees only the context and [ORIGINAL] and returns ORIGINAL. A skipped writer that never reported a price makes the run's cost inexact. These keys need a nanoodle engine with per-node timeout, skip and lock support (nanoodle-js PR #46, merged on main as 9b78fea but not yet released on npm); older engines ignore them, so they show the prompts as inputs again and fail the whole run on one writer error.
