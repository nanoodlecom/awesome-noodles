## Notes

Rewrites a short draft comment so it reads like a person typed it, without changing what it says. This is Nano Maxi's humanize-comment flow v2.7. Five writers rewrite the same draft in parallel, each with its own voice line on a shared base prompt: Qwen3.8-27B Novelist (friend), DeepSeek V4.1 Flash 1017 (forum), TheDrummer Cydonia-24B v4.3 (peer; on mcp.nanoodle.com it falls back to Gemma-4-12B Starry Ocean), Qwen3.8-27B antislop (plain) and Inception Mercury 3 (quick; added 20 October 2026 at Mikkel's request), all reasoningEffort none and maxTokens 600. Each rewrite is joined under a fixed label ([A]..[E]) next to the [ORIGINAL] draft, the post context and the Guidance; the labels are part of the judge joins' separators, so they always stay with their text. A GLM-5.3 decider first checks each rewrite for faithfulness (who said or did what, no new facts, numbers, qualifiers or names, no garbled names, main question and disclosure kept), treats any added explanation, generalization or new claim as unfaithful (when unsure, unfaithful), disqualifies only for unfaithfulness, banned or stock AI phrases, three-part lists, hype, broken grammar or near-verbatim copying, ranks the rest (other style issues such as a dash, a dropped welcome or stiffer wording only lower the rank; direct address to the person and normal sentence casing rank higher, light slang at most once) and picks the most human one that is not disqualified, or ORIGINAL if every rewrite is disqualified. It never picks a near-verbatim copy of ORIGINAL.

Inputs: **Draft** (required; the comment to rewrite, any language, at most 1500 characters), **Context** (required; the post or thread, plain text, at most 3500 characters) and optional **Guidance** (what the comment should do, at most 300 characters; default "a friendly, specific reply"). On mcp.nanoodle.com (nanoodle-mcp) these caps are enforced: a longer input is refused with a clear error before any quote or payment. Characters are Unicode code points. The graph exports the decider's text: a single JSON object and nothing else: {"winner": "ORIGINAL|A|B|C|D|E", "text": "...", "why": "...", "ranked": [{"writer", "model", "text", "faithful", "disqualified", "reason"}, ...]}, where text is the winning rewrite. ranked always has 5 entries, not-disqualified first and best first; each entry carries that candidate's model name (copied from its label line) and its full rewrite. faithful is about facts only, disqualified is true only for the reasons above or a missing writer, and only an entry with disqualified:false can win. A skipped writer is still listed, as {writer, faithful:false, disqualified:true, reason:"missing"} with an empty text. Run through the graph alone (the editor, nanoodle-js or nanoodle-py), the texts are copied by the decider model, so a rare small wording change is possible (seen in testing: "gets lost" became "is lost", and a 458-character rewrite came back 2 characters shorter). On mcp.nanoodle.com, nanoodle-mcp post-processes the decider's JSON. It never passes the decider's texts or model names through: each ranked entry's model comes from a fixed A..E writer-to-model record taken from the graph's join labels and writer nodes (for C, the model that actually answered: Cydonia, or Starry Ocean when the fallback ran), and each entry's text, and the top-level text, comes from the writers' own outputs by writer id after the dash fix below (exactly the text the decider read), so credit can't shift when a writer is skipped and texts are byte-exact. ranked always lists A to E exactly once, eligible entries first in the decider's order. A writer with no output is listed as {faithful:false, disqualified:true, reason:"missing"} with an empty text. An entry the decider marks faithful:false (or anything but true) is forced to disqualified:true, so it can never win. A writer the decider left out is added as disqualified. The winner is the decider's pick if that is ORIGINAL or an entry that is faithful, not disqualified and has text; otherwise the first such entry in ranked order (and why says the pick was replaced); otherwise ORIGINAL, with the draft as text. If the decider's reply is not valid JSON or has no ranked list, none of it is passed through: the result is winner ORIGINAL with the draft as text, all five writers listed with their real texts as disqualified ("not judged: decider reply unusable", or "missing"), and a note leading the tool result says so.

Writer calls on mcp.nanoodle.com (v2.7; nanoodle-mcp hands the run a fetch wrapper, so the engine still makes one call per writer node and the graph is unchanged by it): (1) Fallback: if Cydonia (writer C) answers 429 or 5xx, the request errors, or it has not answered within 30 s, the same request is sent once to gemma-4-12b-it-starry-ocean, which is then credited for C, and a note says so. An x402 402 is passed through, never treated as a failure. (2) Dash fix: in every writer output, a spaced em dash, en dash or hyphen becomes ", " and any other em or en dash becomes ", ", before the decider reads it. (3) Near-copy re-ask: if more than 60% of the rewrite's word trigrams also occur in the draft, the same model is asked once more (its messages, its own answer, then "Your last attempt copied the draft. Rewrite it in your own words ..."), and the second answer replaces the first; no re-ask starts after 35 s, so the writer's 60 s timeout is not put at risk, and both calls are billed and counted in the run's cost. Each fallback and re-ask is listed in a note at the top of the tool result. Run through the graph alone (the editor, nanoodle-js or nanoodle-py) there is no fallback (a failing C is just skipped), no dash fix and no re-ask; the decider still ranks dashes down and disqualifies near-copies.

The prompts and labels are locked: the five writer nodes and the decider carry fields.locked, so their system prompts (the spec's v2.5 writer prompts and decider rubric, with the v2.7 changes below) are not tool inputs and every run uses the stored values. The tool schema is just Draft, Context and Guidance. The block labels "[ORIGINAL]" and "[A] <model>" to "[E] <model>" (each writer's letter and model name, for example "[E] inception/mercury-3") are fixed in the judge joins' separators rather than separate inputs. Changes from the spec's v2.5 decider prompt, all approved by Nano Maxi: the v2.3 line "A missing [X] block means that writer failed.", a missing or empty writer always listed in ranked, a stricter faithfulness rule (no added explanation, generalization or new claim), a role rule (changing what someone is or did, such as roles or who funded, bought or said something, is unfaithful even by paraphrase), per-entry faithful/disqualified/reason, a single-JSON-object output with text inside it, a near-copy rule (a rewrite that keeps most of the draft's sentences or word order is disqualified; prefer the most freshly-phrased faithful rewrite), and model and text in every ranked entry. v2.7 changes, requested by Nano Maxi: Writer A's voice is now sentence case with normal punctuation, direct address (you/your) and at most one light slang word (it used to say "lowercase-ish is fine"); Writer D may copy no more than five words in a row from the draft; Writer C runs TheDrummer/Cydonia-24B-v4.3 ($0.12 in / $0.15 out per M tokens on NanoGPT, 20 October 2026) instead of Starry Ocean; the decider also reads the Guidance (the judge's first join now takes Context + Guidance), disqualifies only for the Step 2 reasons above, and prefers direct address and normal casing (the v2.5 rule against picking a rewrite that drops the direct address is now a ranking preference). Every writer prompt also asks to skip canned praise but keep real warmth toward the person (talk to them, react to their point, keep a greeting or thanks if the draft has one). The decider's maxTokens is 4300 (3000 on the live graph), enough to copy five full 600-token rewrites plus reasons. The cap does not keep a run under the $0.0133 pin: by the v2.7 estimate below the full-maxTokens worst case is above the pin.

On 20 October 2026 three runs of this graph through nanoodle-js main (9b78fea) on two of Nano Maxi's live cases reported $0.00364 (a reply to @pursekeeper's week-7 post; winner E, Mercury 3, 45 s), $0.00287 (an answer to APIS's "what is your rule?"; winner C, which opens "Hi APIS.", 16 s; writer D failed transiently and was skipped, so the cost is marked inexact) and $0.00229 with Writer C forced to time out (week-7 post; winner B, 18 s; D also failed transiently). The decider alone was $0.0019 to $0.0025 of each run. Each returned valid JSON only with 5 ranked entries carrying model names. These are model costs before the 20% markup (about $0.0027 to $0.0044 after). The catalog forecast is $0.009173 before markup ($0.011008 after). v2.7 full-maxTokens worst-case estimate, after the 20% markup: $0.01397524 with no re-ask and $0.01782845 with all five writers re-asked, both ABOVE the $0.0133 pin (v2.6 was $0.01325068). The pin was deliberately left at $0.0133; the minimum that covers the estimate is $0.0179. It takes the enforced input caps (1500 + 3500 + 300 characters), every writer call at its 600-token cap, Writer C at the worse of Cydonia alone or a billed-but-timed-out Cydonia call plus Starry Ocean, each re-ask resending the writer's input plus its 600-token answer and the re-ask line, the decider reading the context, Guidance, draft and five full 600-token rewrites and replying at its 4300-token cap, and the inputs and system prompts at 3 characters per token, which is typical for English. It is an estimate, not a bound. Text that tokenizes worse costs more. For v2.6, counting 1 token per UTF-8 byte for the inputs and system prompts gave $0.02062404 after markup for ASCII text and $0.04001004 for 4-byte scripts; v2.7 is higher still. Those strict figures still rest on an assumption: that the judge sees about 3000 tokens of rewrites (five 600-token writer outputs counted at 600 tokens each in the judge's tokenizer). That is not proven for multilingual text, where a writer's 600 tokens can become more judge tokens, and it is not enforced in code.
